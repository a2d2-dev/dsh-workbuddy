# 本地开源与海外发布评估

评估日期：2026-10-19。代码基线：`06955ff`（`0.1.0`）。本次补充文档，不修改运行代码、不发布 npm 包、不部署线上服务。

结论：适合以自托管、面向已有 DSH 用户的开源 Alpha 继续迭代；尚不适合宣传为完成国际化的正式版，也不适合直接交给运营方提供多人共享的商业托管服务。工程发布准备度约 68/100，属于需要限制范围的小规模试用阶段；该分数不是市场需求评估。

## 已有基础

- 仓库已公开，包含 Apache-2.0 许可证、中英文 README、脱敏截图和 pnpm 锁文件。
- 复用 DSH 的 PiAiAdapter 和独立上游协议实现，没有另造流式及工具调用协议。
- 有账号登录、服务端凭据保存、额度明细、模型搜索、免费筛选和账号模型发现。
- 浏览器路由使用 DSH 鉴权；待完成的登录绑定浏览器；凭据文件原子写入，权限为 `0600`。
- 当前代码文件均少于 1,000 行；现有测试覆盖了模型校验、登录隔离、凭据保存、额度转换和活动有效期等边界。

## 安全和数据处理

本轮扫描了当前可达的两次提交、37 个唯一 Git 对象，检查常见私钥、GitHub/provider token、AWS key、JWT、个人目录和私网地址模式，未命中。这是有限的模式扫描，不是完整秘密审计；已人工查看账号/额度截图中的遮盖情况。

网关允许配置 HTTP，校验通过不等于链路安全；跨主机必须由部署层使用 HTTPS。会话文件是可读 Token，`0600` 不等于静态加密。提示词、历史消息、图像和工具结果会经过网关与 Python 服务发送给上游，不能把“Token 不进浏览器”解释为“数据不离开本机”。

固定版本上游默认关闭 verbose LLM 日志，本地检查确认常规请求使用摘要；详细日志开启后可以记录内容。协议 JSONL 文件没有本插件提供的轮转策略，不能只依赖 Supervisor 的 stdout 轮转。运营方应验证日志、备份及卸载后的删除路径。

GitHub 查询时 Secret Scanning、Push Protection 和 Dependabot Security Updates 显示关闭，且没有 Actions 运行记录。这些属于仓库管理员待处理事项，本次未调整权限或安全设置。安全报告渠道也需实际落地，文档不能替代私密通道。

独立上游在固定版本使用 MIT 许可证，本仓库通过运行时导入使用它，未将其源码复制进仓库。后续若把上游源码和依赖放入统一制品或镜像，需要保留对应许可证及第三方声明。上游账号使用条件、目标地区可用性、品牌描述和可对外承诺的范围，仍需运营负责人单独核实；本轮没有进行服务条款或市场调研。

## 海外市场定位建议

建议首轮聚焦“已经在使用 DSH，并拥有 WorkBuddy 账号的开发者”，主张是账号接入、额度透明、模型发现和 agent 工具工作流。当前交付形态对运维有要求，因此应先收集这类用户的安装与使用反馈，再决定是否投入托管服务。

英文介绍可用：**Connect your WorkBuddy account to DSH, inspect live credits and models, and use streaming conversations with tool calling.** 不建议以永久免费、无限调用或所有国家可用作为宣传点，代码和本地测试没有支持这些承诺的证据。

建议准备三份海外展示材料：独立 DSH 测试环境的英文截图、从安装到第一次工具调用的短演示、英文故障恢复 FAQ。当前截图含有 A2D2/DimAgent 等宿主其他入口，海外演示应清晰说明本插件的独立范围，减少与其他产品的混淆。

DOT 首轮可以用安装完成率、首次成功调用率、首次成功工具调用、后续重复使用反馈及问题解决时间来验证实际需求。先取得用户同意并尽量采用人工试用记录；当前插件没有实现产品分析系统，不应凭空宣称已有这些数据。
